# cfw-render bundled skills

The renderer's **self-contained** recipe closure. Each top-level folder is one
ready-to-run recipe (`SKILL.md` + its vendored `.hub/` dependency closure) that
`bin/cfw-render.sh` renders from directly — the box carries no separate render
toolchain (this is what "make the box stateless", CFW-16, delivers).

**This is a generated, pinned copy — do not hand-edit the recipe folders.**
`scripts/sync-skills.sh` copies the recipes listed in `../config/recipes.json`
from the private source library (`CFW_SKILLS_SRC`, e.g. `~/ecosystem/skills`)
into this tree and regenerates `index.json` + `../config/skills-version.json`.
Any hand edit to a `<recipe>/` folder is overwritten on the next sync and will
fail the checksum gate before then. (The old `cfw-skills-pack` build/publish and
the `git subtree` of `cfw-social/cfw-skills` were retired 2026-09-01.)

---

## Layout

- `<recipe>/SKILL.md` — the recipe entrypoint.
- `<recipe>/.hub/<dep>/` — the recipe's transitive `dependsOn` closure, flattened
  and vendored so the recipe runs offline with no cross-repo lookups.
- `index.json` — the manifest: every recipe, its full file list, a per-file
  `sha256`, a per-recipe aggregate `checksum` + `fileCount`, and a bundle-wide
  `aggregateChecksum`. This is what the integrity gate reads.

## Change the bundle

```bash
# 1. edit ../config/recipes.json to add/remove an allowlisted recipe, then:
CFW_SKILLS_SRC=~/ecosystem/skills scripts/sync-skills.sh   # (run from the repo root)
# 2. confirm the tree matches the manifest (checksum gate):
scripts/verify-skills-bundle.sh
```

`../config/skills-version.json` records the exact source commit this bundle was
synced from; it is regenerated by the sync, never hand-edited.
