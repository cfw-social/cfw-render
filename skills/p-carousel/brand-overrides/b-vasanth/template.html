Idempotency keys on every external write

Without them, retries become double-posts. We learned this with a $5K Slack flood.

What it does
✓Makes a retried call a no-op instead of a second side effect.
!traptimeouts are not failures — the first write often landed. The retry lands again.
Before → after

No key

  • call times out
  • agent retries ×3
  • 3 messages, 3 invoices, 3 posts

Key = hash(intent)

  • call times out
  • agent retries ×3
  • 1 write. The rest return the same result.

03breaks third

Tool allowlist per agent

The EchoLeak (CVE-2025-32711) class of attacks lives here. Reader/Actor split is the architectural fix.

What it does
✓An agent that reads untrusted content cannot also send, post, or pay.
!trapone "do-everything" agent + one poisoned document = exfiltration with your own credentials.
Reader / Actor split

Reader agent

  • search, fetch, summarise
  • sees untrusted input
  • tools: read-only

Actor agent

  • send, post, write, pay
  • sees only the Reader's structured output
  • tools: allowlisted, logged

Human-in-the-loop gates

"Ask a human if confused" is not a gate. Named escalation rules are.

What it does
✓Routes a defined class of actions to a defined person before they execute.
!trapmodels are never "confused" — they are confident. The vague gate fires zero times.
Vague vs named

Vague gate

  • "escalate if unsure"
  • no owner, no SLA
  • fires: never

Named rule

  • any refund > $200 → finance lead
  • any external e-mail → account owner
  • fires: every time, with a queue
